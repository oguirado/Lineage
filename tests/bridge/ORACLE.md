# U20 fail-first oracle

This file maps every numbered Acceptance case in the supplied U20 specification,
including Amendment B. It is a test inventory, not a runtime receipt or ADMIT.
All file references below are repository-relative. Runtime data lives only in
disposable test directories; no live consumer, model, network or terminal is used.

Default suite (the required command):

```text
python3 -m unittest discover -s tests/bridge -t .
```

Set `PYTHONDONTWRITEBYTECODE=1` in the runner environment to keep copied source
read-only. The default suite converts `NotImplementedError("U20 stub")` into a
named assertion failure. Import errors are not accepted as fail-first evidence.
Empty placeholder tool exports and the guide placeholder also fail explicit
assertions identifying the U20 stub. No skip or expectedFailure hides a gate.

Separate prerequisites (Amendment B7):

```text
python3 -m unittest tests.bridge.upstream_gates
```

`upstream_gates.py` deliberately does not match default unittest discovery.
Its schema and CLI cases exercise the actual upstream APIs and fail required
assertions. Receiver-dependent cases fail with `BLOCKED` and `AUSENTE — no inventar`.
These failures are not counted as fake-consumer passes. A future green default
suite cannot establish ADMIT while any prerequisite remains blocked.

## Binding resolutions

- Amendment B1 / M27: no receiver command schema, compiler data nesting, error
  grammar, or argv/stdin carrier is supplied. Do not introduce guessed command
  keys, a stdin field, or positive remote fixtures. Publication/handoff positives
  and their dependent hostile controls remain explicitly blocked. `FakeConsumer`
  checks generic canonical publication and accepts raw hostile bytes only; its
  `fixture` object is observer test data, not a proposed receiver command.
- Amendment B2: same-target retained-intent comparison belongs to the bridge;
  cross-target identity detection is scoped to U05. No home-scoped state layout
  is invented. Actual cross-target crash/recovery acceptance remains blocked.
- Amendments B3/B4: reject NUL/C0/DEL configuration paths before filesystem calls,
  refuse every symlinked lexical ancestor, and retain descriptor-relative safety.
  A relative `paths.commands_dir` is refused with `bad_args`, with no implicit
  base. A named contract is a bounded strict UTF-8 regular file, never discovered.
- Amendment B5 / K0: `operator` and `system` are admitted caller-asserted tool
  actors, without operator authority or level-one access. Tests inspect the
  effective context and immutable application state at the adapter seam.
- Amendment B6: generated details are bounded strings, contain no raw C0/DEL,
  configured paths, secrets or traceback content. Discarding unsafe remote text
  is allowed. Canonical UTF-8 envelope bytes carry the stricter family cap;
  direct dict parsing must still reject non-finite values and bool versions.
- Amendment B7: upstream failures live in the separate suite, never a skip.
  Missing source contracts are reported as blocked assertions instead of fake
  successes. A source-backed amendment must provide fixtures before activation.

## Integrated API adaptations (A-K0-9)

| Owner | Actual API used / preserved discrepancy |
|---|---|
| `lineage/core/registry.py` | `ToolSpec(name, description, input_schema, handler, mutating)`; no `effect`. `Registry` holds immutable maps. Discovery descriptors come from `app.list_tools(registry=...)`, not a Registry method. `load` has keyword-only `package`. |
| `lineage/core/app.py` | `CallContext(home, validators, folds, actor=None, op_id=None)` and keyword-only handler `context`. `dispatch(name,args,context=...,registry=...)` returns `DispatchResult.payload`, `.failure` and `.exit_code`; it already adds `untrusted`. |
| `lineage/bridge/openfresnel.py` | Local frozen `Command(tool,args,agent,op_id,expected_head=None)`; `Context` aliases integrated `CallContext`. No shared `Command`/`Services` or `ctx.services` is assumed. |
| `lineage/core/errors.py` | `LineageError(code, detail=None)`; U20 errors must narrow details to sanitized strings. |
| `lineage/core/schema.py` | `strict_loads(raw)` and `validate(value,schema)`; no `SchemaStore`, `canonical` or `digest`. Shared decoder cap is 65536 bytes [MEASURED: source], unlike the 1048576-byte tool/contract cap [TARGET]. Shared validator lacks `$ref` and logical keywords. No frozen schema is weakened. |
| `lineage/core/cli.py`, `lineage/core/mcp.py` | Existing in-process entrypoints accept injected registry/context and streams. Tests use these actual adapters with the public bridge client seam doubled, without a new dispatcher. |
| `lineage/core/jsonlane.py` | U05 is present and explicitly classifies both bridge names as external. Tests use the actual CLI delegate, recipient-owned endpoint config and deterministic actor/op injection. A client-seam replay is not receiver dedupe certification. |

Placeholder `lineage/ext/openfresnel.py` exports empty `TOOLS`, `VALIDATORS` and
`FOLDS`, with callable raising stubs. This preserves unrelated registry loading.
The oracle still requires both exact mutation-sensitive descriptors; the empty
placeholder does not satisfy registration. Publishing the unsupported spawn
schema globally during stub setup would break unrelated existing tests.

## Oracle discrimination and evidence boundaries

Each test uses named positive, negative or hostile contrasts. Configuration
selection positives distinguish an allowed real directory from invalid/symlinked
ones. Mutation controls first require the real refusal, then run the same
assertion against an in-memory success double that bypasses mode/family checks.
The observer rejects partial, noncanonical, duplicated-key or nonobject finals.
Identity, retry and actual publication mutants cannot be claimed killed without
an authoritative positive control; their gates remain blocked. No frozen test
file is edited during a control.

The default fixtures patch subprocess/network/signal entrypoints and refuse
writes outside each disposable runtime. They do not launch a process or send a
signal. Virtual monotonic time and virtual waits bound polling; no fixed real
sleep establishes readiness. FIFO controls reject a blocking open before it can
hang. File/descriptor fault and receiver-retry positives await the missing ABI.

Evidence stages remain distinct: specified, stub-red, fake-consumer-green,
transport-integrated, live-verified. Client-seam doubles prove adapter behavior
only. `state:"launched"` is not run completion, memory admission, a journal event,
a benchmark result or a verified ledger witness. Runtime receipts are external
to this inventory. Live OpenFresnel compatibility and headless terminal parity
are AUSENTE; no historical receipt or syntax check changes that status.

A1 integration scope is checked externally against the untouched source
manifest. Public-coordinate checks here are deliberately narrower than an
unavailable campaign publishability checker; the corresponding full gate stays
blocked. `docs/OPENFRESNEL.md` is a placeholder required to fail guide coverage
until the public implementation guide exists.
